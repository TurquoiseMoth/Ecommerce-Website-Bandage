# Bandage Ecommerce Website — Project Notes

This file is the single source of truth for the state of the codebase. It is
written for three audiences: developers, non-developers, and AI chatbots.
Each section says who it is for.

---

## 1. What This Project Is (for non-developers)

We are rebuilding the "Bandage" ecommerce website (a Figma-style template:
homepage, product listings, product detail pages, shopping cart) as a modern
single-page web app. It pulls real product data (images, prices, ratings,
reviews) live from the DummyJSON public API. The finished site is meant to look
like the Bandage design reference and work on both desktop and mobile.

Nothing here is deployed to a live URL yet — it runs locally on your computer
via a dev server.

---

## 2. Tech Stack (for developers)

- **React 19 + TypeScript** — UI framework + type safety
- **Vite 8** — build tool / dev server
- **React Router 7** — client-side routing (/, /product/:id, /cart)
- **Redux Toolkit + React-Redux** — global state (shopping cart)
- **RTK Query** — data fetching/caching for the DummyJSON API
- **Vanilla CSS, BEM-style class names** — per-component `.css` files imported
  alongside each component. No UI library, no CSS framework, no Tailwind.

---

## 3. Architecture (for developers and AI chatbots)

Folder responsibilities:

```
src/
├── main.tsx               Entry point: <Provider store> + <App/>
├── App.tsx                Router — defines all routes
├── index.css              Global reset only
├── app/store.ts           Redux store (cartSlice + productsApi middleware)
├── types/product.ts       Shared Product / ProductReview interfaces
├── services/productsApi.ts RTK Query: getProducts (→ /products),
│                            getProductById (→ /products/:id)
├── features/cart/cartSlice.ts  Cart reducer + selectCartItems
├── components/            Reusable presentational components
│   ├── Header/            Top bar + main nav + mobile menu (cart badge linked)
│   ├── Footer/
│   ├── ProductCard/       One product card (clickable → /product/:id)
│   ├── ProductGrid/       Maps Product[] into ProductCards (columns prop)
│   ├── QuantityControl/   − / + stepper with read-only value input
│   ├── CategoryShowcase/  Homepage hero/category tiles
│   ├── FeaturedPosts/     Homepage posts row
│   ├── Services/          Services section + CtaBanner
│   └── Testimonials/      TestimonialCard
└── pages/
    ├── Home/              Homepage: showcase + bestsellers + services +
    │                        posts + testimonials + CTA
    ├── ProductDetails/    Gallery, ProductInfo, tabs, bestsellers, companies
    └── Cart/              Cart list (CartItemRow) + order summary +
                             related products
```

Data-flow pattern:

```
Home / ProductDetails / Cart
  → useGetProductsQuery() | useGetProductByIdQuery()   (RTK Query hooks)
  → ProductGrid → ProductCard
Cart
  → useAppSelector(selectCartItems)                    (Redux state)
  → CartItemRow → QuantityControl
```

Conventions:
- Pages own data fetching and page layout; components are reusable and mostly
  presentational (take explicit typed props).
- `Product` is the single source-of-truth type for API data — never invent
  fields that are not in `src/types/product.ts`.
- Prices are displayed in USD `$` format (e.g. `$12.99`). The design used `€`
  in some references, but the site-wide decision is `$`.
- Brand colors: accent blue `#23A6F0`, success green `#23856D`, dark
  `#252B42`, background `#FAFAFA`, muted gray `#737373`.
- Every feature is built and verified cell-by-cell, then `npm run build` +
  `npm run lint` must pass before moving on.

  fallbacks used).
- Not deployed; static `dist/` build only.

### Route map

- `/product/:id` — Product details

## 7. Commands (for developers and AI chatbots)

```
npm run dev       # start local dev server (Vite)
npm run build     # tsc -b && vite build  (type-check + production build)
npm run lint      # eslint .
npm run preview   # serve the built dist/
```

- API: `https://dummyjson.com/products` and `/products/:id`
- Browser check after each change: Home `/`, product `/product/1`, cart `/cart`.

## 8. Handoff Notes (for AI chatbots)

- This is a snapshot, not a live tree — run `git status` / `git diff` before
  proposing changes; a cell may already be partially done.
- Continue the established architecture (React + TS + Vanilla BEM CSS + Redux
  Toolkit + RTK Query). Do not introduce new frameworks/libraries.
- Work in small increments and verify each step (`npm run build` + `npm run
  lint` + browser check) before moving on.
- Use explicit typed props; keep components small and single-purpose.
- Do not invent `Product` fields or API behavior beyond `src/types/product.ts`
  and DummyJSON.
- Prices are `$` USD. Use brand colors listed in section 3.
- Do not commit unless asked.
